## 本轮完成内容

- 增加配置化日志格式适配，支持标准 message 日志和结构化 event 日志。

## 数据与范围映射

| 故障项目字段 | 实际来源 |
|---|---|
| service=enterprise-indexing | 索引能力的逻辑名称，关联 Worker 日志和 API 导出的队列/心跳指标 |
| environment=staging | 故障项目的本地测试环境名称；Loki 实际 environment 标签仍为 local |
| service_version=local-v1 | 管理员登记的接入版本，不代表自动发现的业务发布版本 |
| workers_active | sum(enterprise_indexing_workers_active{job="enterprise-knowledge-api"}) |
| queue_depth | sum(enterprise_indexing_queue_jobs{job="enterprise-knowledge-api",status="queued"}) |
| resource 日志 | {stack="enterprise-knowledge",service="worker",environment="local"} |
| owner / runbook | 本地服务登记；历史案例和变更仍未填写 |

Prometheus、Loki 使用已登记的本机地址。Agent 不接收任意端点、查询文本、凭据或文档检索权限。以上指标是系统级运维数据；tenant_id/users 限制谁能使用登记，并不会自动将指标拆成业务租户。若要接多团队共享环境，管理员须在查询与日志选择器中增加真实隔离标签。

## 日志适配规则

app/providers/logs.py 的 LogMapping 使用 Pydantic 校验配置。可登记 message_field、level_field、error_code_field、event_field、detail_fields、event_only、event_allowlist。

普通日志默认使用 message；缺少有效 message 且存在有效 event 时，将事件转换为描述。知识库登记使用 event_only=true，必须有 event_allowlist：仅保留已登记事件，忽略原 message、纯文本和未知事件。

允许的详情字段为 count、attempt_count、indexed_chunk_count、duration_ms、heartbeat_seconds、metrics_port、status、outcome、error_type、queue_depth、active_workers。只接收有限且有界的数值、布尔值和短标识符，不展开字典、列表或自由文本。

知识库映射未包含文档编号、租户编号、知识库编号、用户问题、文档正文、异常堆栈或令牌。缺少真实日志级别时保留 UNKNOWN，不根据 failed/started 等事件名称推断 ERROR/INFO。带 level=ERROR 的查询不会匹配 UNKNOWN，首次查询应省略 level。

app/providers/http.py 在证据生成前对消息执行脱敏，覆盖带引号的凭据字段、Bearer、连接 URL 中的用户名密码和 sk- 密钥格式。超过消息长度限制时标记内容截断；元数据或空 message 不再生成空白日志证据。

resource 在本次映射中表示 Worker 与索引任务的运行事件，不表示已确认资源不足。dependency/configuration 尚未登记独立的来源分类，不将同一批日志复制成多种类别。event_only 可能排除有用的纯文本异常；这种格式的接入需后续设计专用脱敏规则，不能声称所有错误都已覆盖。

## 免费联调如何运行

从本项目根目录执行，无需先启动故障 HTTP 后端：

```powershell
cd D:\code\it_incident_agent
$env:PYTHONIOENCODING = 'utf-8'
.\.venv\Scripts\python.exe scripts/probe_registered_service.py --service enterprise-indexing --minutes 1440
```

脚本加载 .env.local/.env 和 INCIDENT_SERVICES_FILE。也可显式指定 --services-file services.local.json。默认选取本地私有凭据文件中的唯一 operator，并通过与后端相同的认证函数验证令牌；多身份时使用 --user 和 --tenant 选择。凭据不会打印。

执行顺序：

1. 在当前身份可见的服务目录中定位 service/environment/version。
2. 构造临时只读范围；不创建业务工单，不写数据库。
3. 每个指标单独查询最近最多5分钟，使用5分钟粒度，避免超过既有证据响应大小限制。这里只检查样本可读性，不分析完整故障趋势。
4. 日志按 --minutes 指定窗口查询（默认60分钟，最大1440分钟），每个已登记类别最多取51条，保留最多50条，并明确标记截断。
5. 查询本地负责人、适用排查手册。
6. 通过真实工具执行器生成证据与引用，逐条校验 value/message/team/text 引用和原始证据字段一致性。

所有检查共享 RunContext，模型预算为0、工具尝试预算为12、总时间预算为180秒。最多检查前7个登记指标，超过时报告未检查项。故障系统和知识库的模型 API 均不会调用。不会调用问答、上传、修复或工单创建接口。

汇总输出包含状态、证据数量、已验证引用数、日志级别统计、过滤/丢弃计数、少量指标值、窗口和用量；不输出原始日志、事件文档或凭据。默认保存到 output/registered-service-probe.json，该目录已忽略提交。run_id 仅对应本次临时联调追踪，不是数据库中的诊断运行，不能用 GET /runs 读取。

退出码：0=已配置检查均通过且无截断；2=有空结果、缺失指标或截断等信息缺口；1=身份、登记或参数等原因导致无法开始。空日志表示当前选择器/窗口没有可用观测，不代表故障，不会自动扩大范围、调用模型或重启服务。网络错误保留为 error，不伪装成 empty。

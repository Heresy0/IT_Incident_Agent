# M5 输入与只读补查修复记录

日期：2026-10-08。基于 `codex/incident-foundation` 的 `fbf3578` 修复上一轮真实复测发现的三个问题：单 Agent 输入超限、不可执行的扩容返工请求，以及 ERROR 空结果后的日志遗漏。本轮付费调用为零，未读取 Key 或令牌；已有运行报告、gold 和审计提交保留。

## 改动与运行流程

**模型输入压缩。** 新增 `app/mult_agents/incident/model_view.py`，模型只接收指标/日志/变更/知识正文的必要字段、来源身份与时间，以及有实质内容的引用选项。重复的完整 excerpt、hash、locator、所有元数据字段的引用目录不再逐轮放入 ToolMessage；完整快照、字段路径、哈希和原始引用注册表仍在服务端保存，并写入原有运行报告。Investigation、SingleAgent 和协作来源摘要共用同一投影，引用校验仍针对完整原始快照。

取证对话接近输入上限时，将旧的模型/工具轮次整理为注册证据和最近十二条查询结果。保留系统指令、原工单、范围与输出合同，保留最终输出或修复提示；移除旧工具轮次时一起移除工具选择及对应响应，不留下孤立 ToolMessage。为后续输入留出最多 4000 字符空间。如果完整必需上下文仍无法容纳，原 Harness 输入门禁照常拒绝；如果模型视图省略了部分证据，记录省略数量，输出缺口且保守保持 partial，不把缺少展示当作观测不存在。

新增 model_input_view=compact_sources_v1、model_input_compacted 事件及 model_input_omitted 标记。工单源码指纹纳入新模块；输入上限仍为 28000，模型/工具/时间预算与步骤上限不变。

**补查为结构化只读请求。** EvidenceRequest 增加 checks，最多两项，每项指定六个现有只读工具之一及其参数。Reviewer 收到该角色可用的工具合同和服务/环境/版本/时间范围；可补查预算还考虑即将发生的 Reviewer 和 Supervisor 调用。自然语言 proposed_check 只作说明，不能授权操作。

补查先复用 ToolExecutor.validate_args 校验角色、身份、工具参数、时间窗和服务范围，预检查不占调用次数、不执行 Provider。越界、已完成的相同查询或没有 checks 的提议不会派发；保留不确定性和人工待确认说明，不消耗结构修复额度。扩容、回滚等实验没有对应只读工具，留在 missing_information。旧报告中没有 checks 的请求仍可读取，但不作为新自动返工的可执行计划。

Supervisor 派发获准的角色后，Investigation 收到程序固定的任务说明及 approved_checks。取证模型只能选择获准工具和规范化后完全匹配的参数；即使替换为同角色通常允许的其他工具，也会在实际调用前被 CHECK_NOT_APPROVED 拒绝。获准检查没有完成则保留明确缺口和 partial。实际执行仍由已有 ToolExecutor/Harness 完成，模型/工具逐步计数；最多一次返工和两次复核的边界保留，没有新增角色或第二套循环。

**ERROR 空查询保留过滤缺口。** 空的 ERROR 日志查询记录已验证的类别、时间窗和错误码过滤。模型会收到省略 level、按同类别和时段检查 WARN/INFO 的反馈；不自动执行查询。只有未截断、覆盖原窗口且没有更严格错误码过滤的无 level 查询，才消除这项过滤缺口。重复查询、拒绝和截断不会假装补齐。

若模型直接给最终输出且缺口仍在，正常步骤内最多再反馈一次；仍未检查或预算不足，则 missing_information 明确说明并保持 partial。缺口随共享 Executor 带给后续任务和 Reviewer，原因不能被接受为 supported；即便报告只批准了事实，没有提出假设，协作也不会掩盖这项已知缺口而完整结束。CPU 缺口与来源字段生成事实的上一轮约束继续生效。

运行路径仍为：工单 → 动态取证/知识查询 → 紧凑模型视图与完整引用校验 → Diagnosis → Reviewer → 获准的只读补查或人工待确认 → 有界收尾。没有页面扩展、权限放宽、隐式写操作或付费执行。

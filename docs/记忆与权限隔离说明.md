# 演示级身份隔离与两层记忆

本次在 `codex/memory-isolation` 分支完善现有研究助手，保留八个角色、十一个节点和已有证据校验流程。API 使用 `ScopedMemoryManager`，不再调用会回退到未完整隔离 SQLite/Redis 存储的旧管理器。旧实现保留给独立 CLI 实验使用，不能据此宣称所有旧后端都完成了安全改造。

## 身份与授权

运行 `python scripts/setup_demo_auth.py` 会生成三组随机令牌：`team_a/alice`、`team_a/bob`、`team_b/alice`。服务端 `.auth.local.json` 只保存令牌 SHA-256 摘要与身份；明文令牌放在 `.demo-credentials.local.json`。两个文件均已加入 `.gitignore`，初始化脚本不会覆盖已有文件，也不打印令牌。

浏览器粘贴令牌，调用 `GET /api/v1/auth/me` 验证，之后所有研究与记忆请求携带 `Authorization: Bearer <token>`。身份字段由服务端绑定；兼容提交相同的旧身份字段，提交其他身份返回 403。缺失或无效令牌返回 401，服务端配置缺失返回 503，不允许匿名降级。

运行记录和事件 SQL 都带 `tenant_id`、`user_id` 条件。不同用户即使拿到同一个 `run_id`，结果查询和 SSE 回放也返回 404。运维身份仅额外允许访问聚合 `/metrics`，不能读取他人研究或记忆；`/health` 保持公开。修改注册表会在下一次 HTTP 请求生效，已建立的流不会主动撤销。

前端身份字段只读，令牌与运行指针保存在当前标签页的 `sessionStorage`。保存指针时不保存原问题正文，退出清除当前身份缓存并中断客户端请求；新建会话生成新 `thread_id`。退出浏览器连接不取消后端任务。

## 两层记忆

| 数据 | 存储与隔离键 | 用途与保留策略 |
| --- | --- | --- |
| 当前会话消息与摘要 | PostgreSQL `assistant_sessions`；租户＋用户＋会话 | 衔接同一会话，默认最后活动后 7 天过期 |
| 用户画像 | PostgreSQL `assistant_profiles`；租户＋用户 | 称呼、中文/英文、表达风格；用户修改或删除前保留 |
| 明确保存的背景 | PostgreSQL `assistant_memories`，Milvus 辅助索引；租户＋用户，可配置会话级检索 | 180 天有效，单条 1600 字符上限 |
| 已完成任务历史 | 同上；保存运行 ID 与来源类型 | 可选，`SAVE_CONVERSATION_TASK=false` 默认关闭；开启后保留 90 天 |
| 图检查点 | 原 LangGraph PostgreSQL Checkpointer；独立 `run_id` | 保存单次研究图状态，不充当跨请求聊天记录 |

默认消息超过 30 条时压缩，保留最近 20 条；消息总字符数超过 16000 时也压缩，近期窗口会进一步缩小至不超过 12000 字符。滚动摘要最多 1000 字符，单条消息最多保存 6000 字符。摘要模型使用 Qwen-Plus，经原 Harness 的模型调用与预算边界执行；模型不可用或预算不足时保留有界文本摘要，避免压缩失败丢掉最新一轮消息。这些是字符与消息数限制，不是精确 Token 计数。

同一用户的记忆写入采用 PostgreSQL 事务级 advisory lock。消息追加、摘要和窗口裁剪在同一事务中提交，避免并发读改写覆盖。数据库事务不覆盖外部模型和 Milvus 服务，所以仍不是跨存储强一致；摘要期间会持有该用户的事务锁，适用于当前小并发演示规模。

普通研究问题不会自动变成偏好。自动记忆只识别非常窄的显式称呼/表达风格句式，例如“我叫小李”“以后用通俗语言回答”；更多偏好通过页面表单明确保存，背景通过单独输入框保存。偏好更新覆盖旧字段，内容哈希用于长期记录去重。

## 检索、过期与删除

Milvus 新记忆集合使用 `<MILVUS_COLLECTION>_scoped_v2`，避免复用旧集合的不完整元数据 schema。相似度检索传入租户、用户过滤表达式，先限定范围再 top-k；会话级配置还加入 `thread_id`。取到的 ID 继续查 PostgreSQL，核验归属和有效期，注入使用数据库正文，不信任向量副本正文。向量服务失败时只在同一授权范围内做 PostgreSQL 关键词回退，召回质量可能下降。

删除立即作用于权威表，旧向量即使命中也不会注入。删除或手动更新画像会增加用户记忆版本；开始研究时记录版本，结束时版本变化就跳过此次自动写入，防止删除被在途任务重新写回。清除单个会话保留画像与长期记录，清除长期记忆保留会话，清除全部才移除本人所有记忆。

向量副本目前不会同步物理删除，也没有自动补偿队列或重建任务；这些旧行占用空间但不作为有效记忆返回。过期判断在读取时立即生效，物理清理可由本地管理员执行 `python scripts/cleanup_memory.py`。用户画像通过手动管理移除，没有自动过期。

旧版记忆表与向量集合不会自动导入新系统，避免把未核实归属的历史资料带入。旧运行仍保留原归属，访问令牌必须匹配其租户与用户；不会批量把历史运行改挂到演示账户。

## 私有知识资料

公共资料必须由管理员显式配置 `RESEARCH_PUBLIC_KNOWLEDGE_COLLECTION`；未分类的旧集合不会直接共享。本机 `tech_selection_v1` 的四个片段已逐一匹配仓库 `examples/tech_selection` 中的公开笔记后设为公共。

私有资料分为租户共享与用户私有两个集合，集合名由服务端对基础集合名及身份做哈希生成。检索只打开“显式公共＋当前租户共享＋当前用户私有”三个范围；HTTP 请求和模型均不能指定任意集合。入库仍沿用原 TXT/Markdown 入口，属于可信的本地管理员操作，没有增加上传接口或外部管理入口。

```powershell
# 公共集合先在 .env.local 配置 RESEARCH_PUBLIC_KNOWLEDGE_COLLECTION
.\.venv\Scripts\python.exe local_run.py ingest examples/tech_selection --public
# team_a 成员共享
.\.venv\Scripts\python.exe local_run.py ingest "D:\资料目录" --tenant-id team_a
# 仅 team_a/alice 可检索
.\.venv\Scripts\python.exe local_run.py ingest "D:\资料目录" --tenant-id team_a --user-id alice
```

入库仍会追加文档，不要重复导入本机已存在的四份公开笔记。

## 记忆接口与页面使用

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/auth/me` | 获取令牌绑定身份 |
| `GET /api/v1/memory?thread_id=...` | 本人画像、指定会话和有效长期记忆 |
| `PUT /api/v1/memory/profile` | 替换称呼、语言、表达风格 |
| `POST /api/v1/memory/notes` | 明确保存一条背景，支持可选会话 ID |
| `DELETE /api/v1/memory?target=session&thread_id=...` | 清除本人指定会话 |
| `DELETE /api/v1/memory?target=entry&memory_id=...` | 删除本人指定长期记录 |
| `DELETE /api/v1/memory?target=long_term` | 清除本人画像与长期记录 |
| `DELETE /api/v1/memory?target=all` | 清除本人全部记忆 |

记忆管理接口不接收用户或租户覆盖字段。`ENABLE_MEMORY=true` 控制服务端能力；每次研究仍需勾选“启用会话记忆”，默认关闭。不勾选不会为该研究初始化、读取或自动保存记忆，页面手动管理是独立的明确操作。记忆服务不可用会记录 `MEMORY_UNAVAILABLE`，研究继续执行，不切换到未隔离后端。

在本机打开 `.demo-credentials.local.json`，复制一个 `token` 到页面并验证。`team_a/alice` 带演示运维权限，其他两组可用来演示同租户不同用户和同名用户跨租户隔离。

后端已重启，本机实际 HTTP 检查通过：三组令牌绑定正确，缺失身份返回 401，伪造身份和普通用户读取运维指标返回 403，记忆读取与前端代理正常。这轮运行检查没有发起新的研究，也没有调用付费模型、搜索或 Embedding。

表达偏好只影响注入记忆的节点；最终报告沿用中文程序模板，本轮未增加全报告翻译或风格改写。

## 面试口述：两层记忆怎么设计？

我把对话记忆和图检查点分开。Checkpointer 保存一次研究的执行状态，用独立的 run_id 隔离；短期对话记忆存在 PostgreSQL，以租户、用户、会话三元组定位。默认超过 30 条消息触发滚动摘要，保留最近 20 条，还设置字符预算和 7 天会话有效期。摘要调用 Qwen-Plus，失败时退回有界文本摘要。追加消息和裁剪窗口在同一事务里提交，并通过数据库锁避免并发覆盖。

长期记忆分成明确的用户画像、用户保存的背景，以及可选的完成任务历史。PostgreSQL 是权威存储，Milvus 是检索索引。我不会把普通问题自动记成偏好，也不会把旧任务答案当成新研究的证据。用户能查看、修改、删除自己的记忆。

## 面试口述：身份隔离与记忆注入怎么做？

访问令牌先在服务端映射到租户和用户，客户端不能通过修改身份字段越权。运行结果和 SSE 事件查询带归属条件；短期记忆再加上会话条件。长期记忆检索先在 Milvus 中按租户和用户预过滤，召回的 ID 再回 PostgreSQL 校验归属、有效期和是否已删除。

在进入研究图前，Service 读取画像、近期对话、摘要和相关历史背景，生成最多 2800 字符的结构化上下文。`with_memory_context` 将它作为低优先级历史数据放进部分节点的用户消息，不是放进系统提示词。verify 和 write 不注入记忆，结论仍须由本次证据支持。清除记忆会增加版本号，在途任务使用旧版本就不能写回，避免删掉的内容再次出现。

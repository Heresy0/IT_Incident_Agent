日期：2026-10-07。分支：`feat/tech-selection-finish`。工作流版本：`harness-v1.2-evidence`。

## 1. 交付定位

面向企业技术选型前期，输入候选与约束，结合联网搜索摘要和本地资料形成带引用的研究初稿，显示未确认问题。当前可作为本地演示与简历项目；复杂推荐需要人工核对，不能替代真实部署、性能测试和采购决策。

系统保留8个角色、11个节点。规划与反思复用Planner，取证审计与支持复核复用EvidenceJudge；工具由Python节点执行。网络与本地分支汇合，最多一轮分析后补搜，复核后仍是写作/收尾，没有新增自主工具循环或Reviewer反馈回路。

## 2. 本轮完成的工作

### 复核状态修复

真实固定资料q11首次评测出现：所有必要问题已覆盖，额外的费用结论被拒绝，程序仍给missing_gaps加“部分结论已排除”，从而返回partial，并写“尚未完整回答”。

修复将候选排除记录与必要问题缺口分开：

- 原有来源、引文、限定条件和支持性检查保持有效。
- 被剔除结论不进入正文，留在verification_rejections和报告“复核排除”栏。
- 是否还有研究缺口由复核返回的实际缺口及接受结论的覆盖关联决定。
- 若必要结论被剔除，覆盖仍会降级为partial/unanswered，最终仍返回有限结果。
- 不把恢复后的报告状态修改写回历史数据库记录；旧结果保留原状。

新增一项回归包含上述两个方向。不是放宽事实校验，也不代表completed等于事实全部正确。

### 演示与配置

新增`scripts/demo_research.py`：明确区分付费新研究与GET回放，检查事件连续性、终态结果及回放不增加用量，按时间与run_id保存记录。

统一记录工作流版本，服务和离线评测复用`harness/version.py`。`.env.example`模型与补搜示例同步为qwen-turbo/1；没有覆盖本机真实Key和配置。

更新README、Windows运行说明、评测说明与面试稿。公开报告快照及最小元数据加入`docs/demos/`，原始事件、日志和失败校准继续留在忽略提交的output中。

此前已完成的额度分类、紧凑来源ID、结构校验、官方入口目录、范围控制和引文选择修复一并保存为当前代码基线，详见《证据整理输出修复说明》。

## 4. 演示与使用

1. 按README_LOCAL启动Docker、后端8002、前端5173，端口已运行时直接访问。
2. 阅读docs/demos中的报告，练习说明来源、条件和缺口。
3. 优先使用脚本`--run-id`回放已有记录，不再次消耗外部额度。
4. 需要现场新研究时，使用`--case ... --live`；已导入的笔记不要重复入库。
5. 页面展示同一个run_id、问题覆盖、用量和来源；刷新应读取原运行。

完整命令和运行ID见[演示目录](demos/README.md)。数据只在本地Docker卷；新机器需要建立自己的运行记录。

## 6. 交付边界

当前不自动选择工具，不动态协商；官方目录仅覆盖已登记的Dify/FastGPT；网络只读摘要。本地RAG仍是TXT/Markdown、基础向量检索、重复入库追加。

默认API记忆关闭；检查点与事件保存不等于长期记忆或崩溃续跑。单后端进程、默认2个并发任务；用户/租户字段不构成认证。时间预算在调用边界检查；模型/Embedding底层HTTP尝试和费用未知，不能精确报成本。

可以作为现有版本的工程收尾基线，不再扩展新Agent或基础设施。后续增强应由具体失败案例或岗位需求驱动，并保留此版本用于回退。

## 真实试点证据

### 1. 只读诊断完成

已有运行 `7a089e92-e1b5-4ab2-80c3-fc58a655cfae` 经只读结果接口核对：

- `execution_mode=live`，`workflow_engine=langgraph`，`purpose=diagnosis`。
- `status=completed`，`review_status=passed`，`business_result=diagnosis_available`。
- 4 条事实、1 条原因假设、1 条处理建议；8 次模型调用、2 次工具调用。
- 0 轮返工、0 次结构纠正，终止原因为 `FINISHED`；费用未估算。

该诊断取得活跃 Worker 为 0、队列深度为 1 以及 Worker 停止事件等观测，支持“缺少活跃 Worker 导致排队任务无法执行”的当前故障机制。建议人工核查维护安排和启动条件。Worker 为什么停止仍是独立的触发原因问题；稀疏采样不能证明整个窗口内持续异常。

本次收尾只读取这个已有结果，没有发起新的诊断。真实调用质量的证明来自这一运行，免费脚本替身成绩不作为自主诊断准确率。

### 2. 人工恢复与索引重试

用户人工恢复 Worker 后，索引任务曾在第三次尝试失败，错误为 `Connection error.`；这属于后续向量模型调用的连接问题，不能与原来没有活跃 Worker 混为同一故障。

前序排查确认容器 DNS、TCP、TLS 和普通 HTTP 可达。用户明确授权了一次实际 Embedding 测试，输入仅为“连通性验证”、自动重试为 0；返回 1 个 1024 维向量，记录 Token 为 5，说明该次接口调用成功。该单次授权已经使用，本次收尾没有重复调用。

之后用户在业务页面重试并反馈“成功了”。本记录将它作为用户确认的索引恢复结果，不扩展为已经验证文档搜索正确、系统长期稳定或自动修复通过。

### 3. 尚未确认的业务状态

未对文档检索进行新的独立检查，未读取并确认该业务任务的最终数据库字段，也未调用工单解决接口。诊断完成与工单解决是不同状态；在操作人员确认业务恢复前，不能因报告通过而自动将工单置为 resolved。

用户反馈服务问题不必提供索引任务 ID。症状、发生时间、服务和影响范围即可开始范围内诊断；任务 ID 只是在需要核查特定业务任务时提供的辅助信息。

## 语义核查与验收缺口

以下由 Codex 对原始返回、所选引用及独立 gold 做辅助审阅。辅助审阅存放在原目录的 assistant-review.json，approved=false；正式 comparison.json 保持 manual_review_pending，业务准确率和支持率保持 null，等待人工确认。

1. **SingleAgent 缺必要健康对照。** DB ping 正常已经返回，但不能代替 db_cpu。假设的 counter_refs 与 pending_checks 均为空，最终信息缺口没有指出 CPU 尚未检查。工程上的 completed 不能证明该业务排查完整。
2. **SingleAgent 混淆观测类别和因果。** F5 把 scaling 类别的负载变化写成“配置变更”，引用的 summary 只说明负载增加和池上限不变；“可能导致池耗尽”也应放在假设。部分前后比较只引用一侧样本，需引用相应的前后值。扩容建议虽要求人工批准，仍缺 DB 余量、总连接预算及持续饱和验证；查询优化/缓存建议也缺相应观测。
3. **多 Agent 子任务存在来源错配。** 第二个 Investigation 的 F4 用 EV_3393b0277b0b7e51593439fe 的 value=1.0 引用“DB CPU 正常、排除数据库性能原因”，该证据实际是 pool_usage。确定性字段校验无法识别自然语言主语错误。最终 Diagnosis 从原始证据独立选到了 db_cpu=26%，该子任务错配没有成为最终 CPU 数值结论，但中间任务语义仍需纠正。
4. **多 Agent 最终结论仍需要限定。** F1 的 26% mean 值有效，“正常范围/保持正常”属于解释，来源没有返回健康阈值，该句也未引用此前采样。H1 对池容量与负载关系的谨慎假设方向合理，仍应区分应用侧连接池，并引用已经取得的健康对照作为反证；不把建议验证容量效果当已确认根因。
5. **有效的保守收尾已验证。** Reviewer 对 A1 的 uncertain 判断阻止了扩容建议进入最终报告，partial 和升级对象均保留。这是工作流的有效约束，没有模型/解析异常。但本次只有一次复核，无法据此宣布补查修订已经通过真实验收。

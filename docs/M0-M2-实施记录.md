## M1：契约、数据、六个工具

- 新增 `incident/contracts.py`：严格拒绝额外字段，时区归一为 UTC；工单范围为
  Principal 身份、服务、环境、版本、最多 24 小时时间窗和已登记依赖；模型只选受限查询。
- `FixtureProvider` 从服务端中性 catalog 绑定 case；拒绝未登记 ID，绝不由自由工单
  推测演示数据。三个手工合成案例、每案工单/指标/日志/变更/目录/手册/历史数据，
  单独 gold 与 development manifest；没有验收集或生产质量成绩。
- `ToolExecutor` 注册六工具，Investigation 只能用四观测工具，Knowledge 只能用两检索工具。
  执行前核对角色、Principal、绑定 scope、查询窗口/服务；再做同参数去重、原子预算预占。
  指标名单和粒度、日志类别/等级/错误码、变更类别、适用版本/确认状态/归属都实际过滤。
- Provider 数量上限：60 点/指标、50 日志、10 变更、4 手册、4 历史案例；执行器另限制
  每次工具消息约 12000 字符，文本 1800 字符，因此实际返回数可更小，明确 truncated。
  超时/限流/网络错误才允许重试一次，实际尝试均计数；其他错误不重试。
- 配置摘要只允许 auth_mode/auth_audience/pool_max/timeout_ms；未允许字段不会离开 Provider。
  全部观测为 synthetic；这不是已完成生产日志脱敏器或真实监控接入。
- 证据为有界原值 + 程序生成 excerpt、locator、时间、版本、SHA256；重复读取复用首次快照，
  数据变更产生新 ID。正常 empty 不代表系统健康。未确认/过期/其他归属历史被排除。
- 14 项 M1 测试通过：过滤、权限、参数、上限、错误、重试、快照、预算竞态、gold 隔离。
  作者检查脚本验证 3 案时间线、单位、必要区分观测和反证；不输出或宣称模型准确率。

流转：服务端 catalog → 身份绑定工单快照 → 严格工具参数 → 可读记录过滤 → 有界证据快照。
检索是 fixture 的轻量词项匹配；没有调用 embedding/Milvus，不能作为真实召回质量成绩。
M4 的持久化工单归属、API 和人工确认尚未实现；当前只有 CLI 演示目录与只读边界。

## M2：Investigation 循环与 CLI

- 新增 `agents.py/prompts.py/investigation.py/render.py` 与 CLI；复用安装版本 ChatTongyi
  和 Harness 的 invoke_chat_model、ContextVar、原子 reserve、span、事件、usage。
  不使用外层框架 Agent.invoke，不新增五角色、页面或另一套运行存储。
- 模型接收工单必要范围与输出契约，自主返回标准 tool_calls；执行器实际校验/取证后通过
  ToolMessage 反馈；下一步可换工具、提出暂定假设、说明缺口或结束。生产循环没有固定查询顺序。
  `fake.py` 则是明确标注的脚本控制替身，只用于免费回归与演示；没有将其宣称为模型自主选择。
- 单任务最多 4 步（包含结束/修复），结构修复全任务最多 1 次。普通库入口共享 16/24/180
  预算，预留 3 模型/20 秒；旧研究 runtime 默认保持原值。live CLI 的初始小预算为 3 请求/6
  工具尝试；显式 --live 才可联网，--probe 与其相同上限。没有自动批量评测入口。
- task/tool_selected/tool_result/task_completed 与 call_start/end 有 run_id、seq、span、父 span。
  选择与实际执行分开；未知名称用固定 denied 标签，事件不保存模型查询参数或原始秘密。
- 输出字段路径、原值类型/值、单位、时间、版本、真实 excerpt 与 ID 均先由程序核对；
  未验证输出失败关闭，不渲染伪造结论。升级团队必须来自实际读取的目录记录。
  JSON 保留 scope、prompt_version、证据/顺序事件/计数；Markdown 确定性渲染。
- 安装版 ChatTongyi 在 SDK mock 边界完成真正消息转换/工具往返测试：2 模型、1 工具，
  provider 返回的模拟 usage 累计正确；request_timeout=30 到达 SDK；超时无隐藏重试。
  该测试仍为离线工程验证，并未调用真实供应商。模型超时/网络错误分类；其他供应商异常
  由既有 Harness 安全归为 MODEL_ERROR，不公开 SDK 原始异常。
- 16 项 M2 控制测试通过；加上 M1 共 30 项。覆盖任意模型工具顺序、三脚本不同路径、

  输入上限、有限修复、伪造 ID/值/单位/时间/版本/引文、晚到模型/工具结果与提示注入拒绝。

# IT Incident Agent

面向企业内部服务故障工单的多 Agent 协同助手。目标是从工单症状出发，选择只读排查工具、形成带证据的原因假设、复核并定向补查，输出处理建议与升级对象。

**当前阶段：M4 工单工程闭环已完成，免费控制、真实隔离数据库与最小界面操作检查通过。** 可创建/修订工单、启动有界协作诊断、持久化回放和人工确认解决；确认经验仅供当前身份及适用版本检索。原研究入口保留，两个工作流共享执行池和运行存储。M2/M3 的语义引用、必要观测和真实返工修订仍有验收缺口；不把工单工程检查当业务准确率验收。

M5 已完成开发集和对照准备：六个核心开发案例，同预算 SingleAgent/多 Agent CLI、离线汇总及人工语义核查模板。91 项免费回归、六案例共 12 次脚本对照通过。case_003 已完成一次真实单/多对照，共 15 次模型/13 次实际工具调用；机械检查通过，语义引用、健康对照与真实返工仍有缺口。六案例真实对照、12 个独立验收案例及真实观测源尚未完成，M5 尚未整体验收。

最新修复已加入来源字段生成事实、后续任务复用证据、无进展转诊断及连接池 CPU 缺口门禁。98 项免费回归和六案例 12 次脚本对照通过；本轮没有新增付费调用，真实模型效果仍待同预算复测，见 [M5 验收问题修复记录](docs/M5-验收问题修复记录.md)。

## 已有底座

- LangGraph 编排、FastAPI 接口、Vue 页面及 SSE 运行回放。
- 模型与工具预算、有限重试、结构校验、证据与引用审计。

## 已实现的 IT 基础

- 六个中性合成开发案例，三类故障各两个；原三个案例和 gold 保留。观测与独立 gold 分离；不代表生产数据或业务准确率。
- 六个只读工具，执行前验证身份、角色、服务、环境与时间范围；过滤、空结果、错误和截断可区分。
- Investigation 使用 ChatTongyi 标准工具协议，自选四种观测工具；模型选择程序生成的引用编号，程序展开原始字段并严格校验；显式循环逐步计数、去重与有限结构修复。
- 复用原 Harness；工单预算预留调整为 3 次/20 秒，保留旧研究配置。
- M3 新增 Supervisor、Knowledge、Diagnosis、Reviewer；Investigation/Knowledge 共用已有工具循环和运行预算。动态串行派发、逐项复核、最多一次定向补查和修订；历史知识不能单独确立当前原因。
- M4 新增 owner 隔离的工单 API、两张业务表与幂等迁移、数据库启动唯一约束、输入修订快照、运行/final/工单终态事务一致性、operator 人工确认及私有经验检索。页面默认免费流程演示；真实执行必须明确选择模式和预算。自由工单尚未接入真实观测源时明确返回信息缺口。
- M5 的 SingleAgent 对照复用 Investigation 循环、Harness、六工具与协作诊断引用校验；无独立 Reviewer，假设保留 tentative。对照入口统一模型设置、案例快照和预算，保存失败/partial 运行；脚本结果排除在业务评分之外，真实报告需人工逐项核查。
- 协作 JSON 保存任务、证据快照、诊断版本、结构化复核与协商事件；Markdown 由程序生成。免费控制路径完成一次定向补查后修订；真实复测验证了小预算取证及预留收尾，Reviewer 拒绝了证据不足的扩容建议。真实模型未触发返工，部分事实引用语义仍不合格；不把结构有效或 completed 当完整业务验收。
- 免费 scripted CLI 用于控制演示。引用选择协议与最新采样优先已通过真实 qwen-turbo 验证，配置案例取得关键错误日志与配置值。依赖案会追加聚焦查询；两案仍遗漏关键 WARN 日志或对照指标，M2 验收未全部通过。已增加空结果过滤范围反馈与字段说明，最新反馈改动完成免费验证。不把 scripted 路径或 completed 状态当业务质量成绩。

## 后续改造方向

首版覆盖依赖服务不可用、配置错误、资源或连接池耗尽三类故障。

1. 工单与固定案例：症状、观测、变更、人工确认的结果；评测答案与 Agent 可见证据分开。
2. 六个只读工具：服务指标、日志、最近变更、运行手册、历史工单、服务负责人。
3. 有界协作：调度、排查、知识检索、诊断和复核，最多一次定向补查。
4. 诊断报告、证据回放与人工确认；确认后的历史工单可供后续检索。
5. 用同一组案例比较单 Agent 与多 Agent 的诊断质量、调用成本和延迟。

首版只生成操作建议；重启、回滚、删除数据和改权限均不自动执行。

详见 [完整实施与交接方案](docs/IT_Incident_Agent-完整实施与新对话交接方案.md)。该方案为设计材料，实施状态以当前源码和交付记录为准。

## 本地使用

见 [Windows 本地启动](README_LOCAL.md)。本地默认端口：前端 `5174`、后端 `8003`、PostgreSQL `5434`、Milvus `19531`，Docker Compose 项目名为 `it-incident-local`，数据卷独立。

本仓库只包含源码与公开示例，不包含 API Key、认证令牌、运行数据、依赖环境或数据库内容。首次启动需要自行安装依赖并填写 `.env.local`。

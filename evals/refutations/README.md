# 有限反证优化

本轮目标只限于减少“削弱解释、缺少支持被展示为已否定”，以及避免把未知触发来源写入已支持机制。不新增角色、不提高生产预算、不增加自动重试、不拆整个命题体系。

本轮验证后，用户明确选择使用最新版，因此普通 `Collaboration`、`collaborate` 和运行捕获入口默认采用 `bounded_refutation_v1`。显式传入 `review_protection='conservative_v1'` 可回退至前一版保护；`strict_v1` 历史兼容模式保留。新模式沿用基线范围保护，并只给 Diagnosis 与正式 Reviewer 增加简短提示，旧模式不展示新增反证字段。诊断包仍需单独传入，不因复核默认切换而自动加载。

## 反证契约

H 的否定评估增加 `refutation_basis`：`kind` 为直接矛盾、削弱解释或缺少支持；`claim` 为正在质疑的具体命题，简短冲突说明沿用 `reason`。类型为削弱解释或缺少支持、缺少分类、没有当前观测引用、当前观测服务／环境／时间范围不匹配时，程序降为未确认并保存原判定。缺少分类不会单独触发协议重试。

程序先校验所有引用编号，假引用和重复编号仍拒绝。F 与 A 的否定不放宽，核心机制、行动前提、取证覆盖和预算检查保留。降级并不保证减少补查，因此仍需实际验证开销。

直接矛盾标签由模型选择。引用和范围通过后仍不是语义充分性证明：`refutation_basis_retained` 审计事件明确 `semantic_proof_verified=false`。程序不根据原因关键词猜测 CPU、探活、错误码或任何具体行业机制；对象范围仅校验工单服务与环境，无法自动证明是同一次业务请求或同一远端内部对象。真实矛盾和混合命题仍需人工审阅。

## 离线验证

`scripts/verify_bounded_refutation.py --reports <历史验证目录>` 不调用模型或工具。六个成对控制分别验证削弱／缺证据降级、直接矛盾保留。分类由控制输入明确提供，不声称模型会正确分类。历史回放校验原报告哈希，不补造旧报告缺少的分类，因此旧否定降级只是契约兼容行为，不是语义修复证据。

## 一次模型对照

`scripts/validate_diagnostic_packs.py --comparison bounded-refutation --execute-live --cases queue_polling read_only_volume certificate_window --model-budget 24 --tool-budget 16 --input-chars 56000 --output-tokens 3200 --seconds 600`

两边使用相同模型、取证包、场景和预算，每边各一次，交替顺序；失败也保存，不重跑挑选。补充场景在本轮规则完成后编写，验证后不针对结果调参；属于同一开发方的合成材料，不能称为独立盲测或行业准确率。快照、评价标准和计划在首次调用前保存，标准不进入模型输入。

## 预先约定的停止条件

- 引用与范围保护、操作前提或正确反证保留检查失败：修复实现错误后才能验证模型。
- 新模式错误否定增加，或有效机制／下一步被误伤：验证时建议保留旧默认，不扩大保护流程。
- 总词元增加超过百分之二十且没有清楚的质量收益：保留旧默认。此比例是本轮工程取舍，不是统计显著性结论。
- 未出现足够的反证判定，或没有清楚收益：结论为证据不足，保留显式实验开关，停止本轮调参。
- 验证时建议在人工审阅确认有收益、开销可接受时再启用；助手审阅单独标记，不冒充人工或独立质量评分。用户在获知验证局限后明确选择最新版，默认已据此切换，历史审阅结论不改写。

报告分别统计错误否定、正确否定被降级、机制与未知来源是否混写、无必要补查及模型调用／词元。完成率不替代这些指标，货币费用无单价时保持未知。

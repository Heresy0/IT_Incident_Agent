# Diagnosis 引用交付回归对照

应用先冻结，再复验此前失败的三例，每例每组各三轮，共十八次，执行先后按轮次交替。它们已用于定位问题，**不是未见集或独立盲测**。原案例、原准则及原失败记录不修改；第二例部署完成时间的准则缺陷继续披露，不把它当严格时序反证成绩。

新路径的真实JSON Diagnosis调用选择请求内短引用标签；程序精确恢复原引用后，继续执行原始字段、归属、去重、修稿与审批校验。标准流程仍使用原始引用契约和提示词。这里比较的是端到端两种编排，不能只归因于标签长度。

两组均使用原模型配置、16次模型／8次工具／360秒总预算、末稿预留3次模型与20秒，输出上限2200，SDK重试零；含失败在内每轮最多16次付费尝试、整批最多288次。没有预置草稿、复核反馈、标准答案或响应重放。既有一次契约纠正也计入预算，失败终态不得补跑替换。

默认免费计划：`python scripts/compare_orchestration_live.py --suite reference_recovery`。只有显式增加`--execute-live`才调用模型。批次期间应用、驱动、案例和准则保持冻结；保存全部响应、失败事件、查询台账、预算、token、耗时及文件哈希。比较是否形成有效Diagnosis、是否到达有效Reviewer、剩余语义问题与成本，不能把少调用或内部passed直接当效率或准确率提高。

旧十八次、84条响应和24个校验失败事件继续在原目录及公开归档保留，不与本批覆盖或混算。结果与根因分析见[引用恢复说明](../../examples/showcase/diagnosis-reference-recovery.md)。

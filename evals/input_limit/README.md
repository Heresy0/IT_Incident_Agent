# 48000 字符输入上限回归

应用单次完整模型输入默认上限从28000提高到48000字符，包含系统提示、schema、证据和消息历史，不是token数。环境预算入口支持 `INCIDENT_MAX_INPUT_CHARS`，允许4000至128000，空值用48000，超范围截到边界；显式传入的 `Limits` 仍优先。

此前消费者暂停例已交付有效Reviewer并路由到H3修稿，但RevisionDiagnosisSelection输入35844字符被28000门禁拒绝。旧30次运行/130次请求及全部失败保持原样。

新应用先提交并冻结后，三个已见合成案例各一次，模型重新自主规划、生成草稿及复核。不预置草稿/反馈、不回放响应、不调参重跑至通过。它是开发回归，不是盲测或同期配对实验。

固定输入48000；Reviewer4800输出token/60秒，其它角色2200/30秒；温度0、SDK不重试。每运行模型16次/工具8次/600秒，末稿保留3模型/90秒。最多新增48次实际请求，包含失败；之前实际130次，本阶段最高累计178次，低于延续的336次累计上限。身份、证据、修稿范围、审批、角色纠正次数和实际调用计数不放宽。

标准业务流程仍默认legacy，业务模型默认输出2200token/30秒。本次只提高输入预算，保留原评分准则和案例2的发布完成/开始时间缺陷；不计算整体诊断准确率。

免费计划：`.venv\Scripts\python.exe scripts\verify_input_limit.py`。

付费运行：相同命令添加 `--execute-live`。全部原始响应、事件、错误、token、有效稿和失败分流独立留档。

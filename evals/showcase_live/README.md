# 面试展示的真实模型配对

这是一组有目的设计的合成业务场景，使用真实模型自主选择工具与完成角色输出。它与独立测试集、原专项集、免费脚本演示分开记录。数据提供方只有合成快照，不调用真实 IT 服务，不执行修复。

## 两个场景

| 编号 | 业务问题 | 预期能展示的协作价值 |
| --- | --- | --- |
| show_001 | 推送错误、队列积压，历史曾扩容恢复；当前是远端拒绝与编码协议不一致 | Investigation 查当前故障，Knowledge 找历史前提，Diagnosis 对照适用性，Reviewer 复核建议条件 |
| show_002 | 本地健康探针正常，业务导出写入 403，历史是读写连接超时 | 对照业务路径、身份与历史条件，避免“绿色面板=业务健康”或照搬重启存储 |

复用已有六个只读工具与同一个配对执行器。两个链路拥有相同工单、数据、模型、温度、调用预算；单 Agent 可调用全部六个工具。多 Agent 仍是实际串行图，不宣称并行加速。预设业务候选同时提供给两条链路，不把评分答案传入模型。

相对原 probe_001/probe_002，明确业务问题和可查指标，缩短窗口、保留当前样本以减少重复上下文；第二例移除无关旧磁盘事件并补充条件不同的历史存储事件。修改在首次试跑前完成，原快照与结果保留。manifest、答案、快照和 rubric 均冻结；调整必须增加新案例版本，不覆盖旧案例。

## 执行与复核

默认命令只输出免费计划；离线数据检查用 `--check`。真实执行需已有模型与身份配置，以及用户授权后的显式参数：

```powershell
.\.venv\Scripts\python.exe scripts/compare_showcase_live.py
.\.venv\Scripts\python.exe scripts/compare_showcase_live.py --check
.\.venv\Scripts\python.exe scripts/compare_showcase_live.py --live --execute-live --cases show_001 show_002 --model-budget 16 --tool-budget 8
```

首次两例四条运行最多 64 模型调用、32 工具调用。实际消耗从报告读取。执行顺序交替，所有运行（包括失败、partial）写入新批次；先完成运行，再加载评价答案。内部 Reviewer 的 passed 与机械检查通过均不等于外部准确率。助手辅助审阅单独标注，正式人工确认表留待开发者复核。

评价当前机制与引用、历史适用条件、有条件建议，以及复核实际参与或改变草稿的证据。不靠工具次数、角色数量、返工次数或单 Agent 的 tentative 标签判定优势。

展示可以聚焦实际成功样例，但完整批次仍保留。目的性案例不能支持“多 Agent 总是更准”或独立测试准确率；面试应解释它展示的是哪一种协作收益与成本取舍。

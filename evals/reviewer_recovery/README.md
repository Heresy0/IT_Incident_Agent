# Reviewer 截断与契约恢复回归

这是已见开发案例的回归验证，不是独立盲测。冻结应用、驱动、三个原始案例和历史评分规则后，再运行真实模型；不预置草稿、复核反馈或回放模型输出。

- 主对照：3 案例 × 3 次 × 2 流程，共 18 次；两臂 Reviewer 均 4800 输出 token、60 秒超时。
- 小样本探针：相同 3 案例，新流程各 1 次，Reviewer 2200 token、60 秒超时。
- 其余角色均 2200 token、30 秒超时、温度 0、SDK 不重试。
- 每运行模型 16 次、工具 8 次、600 秒；收尾保留模型 3 次、90 秒。实际请求包含失败调用，全批至多 336 次。
- 原始响应、finish_reason、usage、错误、有效草稿、路由和人工交接全部保留；不重跑至通过，不在批次中调参。
- 标准业务流程默认 legacy，默认模型额度仍 2200 token、30 秒；提高额度仅用于该评测。

主对照能比较同额度下两流程的表现，但不能单独归因于接口或提示词。2200 探针各案例仅一次，用于描述输出预算影响，不能作统计因果结论。作者评估不等于独立质量评分。

保留原案例 2 评分规则缺陷：发布完成时间不等于发布开始或生效时间，不据此计算严格时序排除准确率。历史失败档案保持原样。

免费计划检查：`.venv\Scripts\python.exe scripts\compare_reviewer_recovery.py`。

付费执行：相同命令添加 `--execute-live`。执行顺序及各运行预算由 `freeze.json` 和计划固定。

# 冻结实现后的新案例验证

应用指纹固定为 `53e1f1e5008e9018`，不修改提示词、调度、校验或预算规则。三个新编写的合成场景各运行一次：空间耗尽、故障早于发布的 TLS 失败、日志通道不可用。与旧场景存在故障类型重合，本批不是严格独立的保留集，也不是生产数据评估。

`criteria.json` 在调用前写入，`freeze.json` 保存案例、标准及应用版本哈希。运行器只把工单与取证结果提供给模型，不把参考标准送入工作流；对标准文件只做哈希验证。报告先落盘，再验证输出合同，所有失败保留。

使用 Qwen3.7-plus，每例最多 16 次模型调用、8 次合成只读取证、180 秒；单次请求配置 30 秒，不自动重跑失败案例。模型内部 Reviewer 的 `passed` 不是外部正确率。合理的 `partial` 可以满足语义标准；外部请求超时单列为未完成评估，总流程预算耗尽与输出协议错误分别记录。

本地免费检查：

```powershell
$env:PYTHONPATH='app'
$env:PYTHONUTF8='1'
.venv\Scripts\python.exe scripts/run_fresh_validation.py
```

显式使用 `--execute-live` 才会产生模型请求。再次运行属于新的批次，不能覆盖首次结果或替换失败样本。用户随后授权增加预算；使用 `--budget-profile expanded` 选择 32 次模型、48 次工具、300 秒，与默认 baseline 的 16/8/180 区分。原冻结数据和标准不变，每批另存 `execution-plan.json`；保持源码、模型、温度、调度轮次及返工限制不变。单次请求的 30 秒配置也不变。

冻结后的推进标准：先积累新案例和外部人工审阅；仅在同类问题重复出现且影响结论或下一步时考虑修复。修复前说明最小改动和可验证收益，不为单次失败新增特殊规则。

# v2 图检查点与中断恢复

本功能保留七个图节点、四个模型角色、提示词、工具选择规则、默认预算和最多一轮语义返工。目标是进程中断后安全继续原运行；不是根因准确率优化。

## 启用与边界

`INCIDENT_CHECKPOINT_MODE=postgres_v1` 为新接收的运行启用恢复；默认 `off`，显式测试内存存储不支持恢复。运行接收时冻结模式，之后关闭开关只影响新运行。历史运行、原始评估和演示调用账本不迁移、不重置。

恢复继续使用原 `run_id`，LangGraph `thread_id` 也为该值。工单 ID 不能作为检查点线程标识，否则不同诊断会共用状态和额度。

目前仍只支持单后端进程，任务在原有有界线程池执行。恢复扫描是运行调度，不是新的 Agent。数据库会话锁与执行代次阻止重复接管和旧执行者写入。

## 数据职责

| 数据 | 职责 |
| --- | --- |
| 官方 PostgreSQL 检查点 | 七个图节点的调度位置与业务快照引用 |
| `run_execution` | 冻结额度、已用额度、截止时间、执行代次、纠正和返工领取、报告候选 |
| `run_operations` | 每次实际调用准入、请求摘要、原始响应或明确失败、未知结果 |
| `run_snapshots` | 阶段入口和完成时的证据、查询、草稿、审阅、调查问题和运行状态 |
| 原报告和事件表 | 原子提交用户可见的终态，SSE 续读 |

只保存明确 JSON 数据。客户端、凭据、连接和锁在恢复时重新构建；不序列化模型对象，不启用 pickle 回退。

## 阶段内部恢复

当前取证、审阅及返工仍是原来的有界操作。阶段入口快照和操作／事件／时间读数游标共同描述中断位置。恢复时从该阶段入口重建内存状态，按游标复用已提交的调用回执；只有尚未执行的尾部可以请求外部服务。已完成阶段直接装载完成回执。

这个过程会重新执行当前阶段内的本地解析和校验，不重新执行已有响应的模型或工具请求。历史时间读数用于保持原分支和预算提示一致；新外部请求仍由数据库按真实截止时间和累计扣减独立准入。不能拿历史时间读数延长预算。

真实模型客户端使用完整请求调用，不把客户端私有会话状态当作恢复依据。`search_runbooks` 内部的向量请求也保留独立模型扣减；缓存整个工具结果时，同时恢复其子调用的账目、用量和事件。

证据 ID、内容哈希、原始取回时间和引用目录恢复；查询失败、查空、截断和去重状态也恢复。草稿与审阅继续绑定证据包及条目版本，新增来源后原批准仍会失效。来源范围和语义关系仍由现有规则及模型判断。

## 预算与未知响应

每次调用必须先提交预算扣减和操作记录，再发出请求。响应可靠落库后才允许被恢复复用。次数和 Token 用量分别核对，未知用量不记为零，也不能视为厂商账单。

第一次实际执行时固定 UTC 截止时间，停机时间计入总时限。恢复后不能重新获得调用额度、收尾预留或纠正机会。

如果退出发生在请求可能已发送、响应尚未可靠保存的窗口，无法证明外部服务是否已经执行。此时保留扣减、标记结果未知、不自动重发，并交付带明确缺口的有限结果。不能把这类结果计为自动续跑成功。

## 单轮返工与交付

语义返工额度以运行级数据库领取记录为准。同一阶段的恢复复用原领取，不能取得第二轮；本地解析重建不构成第二轮返工。格式纠正也不能因重启增加次数。

图完成先保存报告候选，再由原报告存储在一个事务中提交运行终态、工单状态、`workflow_completed` 和 `final`。候选已保存但终态未提交时，恢复只交付原候选。已结束运行不会重新开启。

SSE 网络传输允许重传；持久化事件按运行及事件键幂等，前端按事件序号去重。数据库未恢复时保留未完成状态，不能声称报告已经交付。

监控只接收首次提交的新事件，不把恢复重建重复计入调用数。监控本身仍是进程内计数，数据库调用账本才是跨进程预算依据。报告候选中的恢复次数属于候选生成时的快照，实际接管次数以运行控制记录为准。

## 验收方式

故障注入用固定模型响应、合成 Provider 和真实 PostgreSQL。子进程通过 `os._exit` 退出，避免只模拟 Python 异常、清理逻辑实际仍执行。

覆盖准入前、准入后未响应、响应已落库、阶段回执领先图检查点、取证和审阅、返工内补证／修订／复审／质询、报告候选及终态提交窗口。独立核验次数上限、未知响应不重发、单轮返工、版本冲突拒绝、执行者互斥和事件幂等。

无故障对照应比较模型请求、工具参数、证据、审阅、报告与用量；归一化仅限已列明的随机标识、时间与恢复元数据。延迟及存储额外开销单独报告，恢复可靠性不能计作准确率改善。

本次真实 Flash 在首个响应可靠保存后主动终止进程，用同一运行 ID 自动恢复。实际 16 次模型、5 次工具、1 轮返工，首个请求只出现一次，Token 与调用账本一致；最终交付 `partial / REVIEW_NEEDS_INFORMATION`，不是根因准确率评分。110.735 秒包含主动停机及恢复等待，不能与普通诊断耗时直接作性能对照。明细见[真实恢复回执](../evals/checkpoint-recovery-20261019/live-recovery-receipt.json)。

该真实原档保留一处重建跨度开始／结束 ID 不一致。之后只修正跨度别名与原始耗时映射，当前源码用故障注入检查完成跨度配对；未为这项监控元数据修正追加真实模型调用。真实运行仍绑定原源码指纹，原报告与事件不改写。

## 回滚

接入前固定点为标签 `rollback/pre-checkpoint-recovery-20261019`。关闭新任务准入开关，等待已开启恢复的任务收尾；部署旧代码前排空或明确结束这些运行。不能让不理解恢复模式的旧服务直接启动并把它们全部改为普通中断失败。

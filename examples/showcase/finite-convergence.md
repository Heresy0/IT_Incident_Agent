# 多 Agent 有限收敛说明

本轮目标是完善已有编排的交接和失败处理，不增加角色、工具或调用预算。

## 调查流程

1. 程序建立症状、机制和合理替代解释的共享证据问题；状态核查只建立症状问题。
2. Supervisor 结合登记能力、已有查询和预算选择有区分价值的检查。已有问题由程序保留，任务结束不自动关闭问题。
3. Investigation 执行范围内只读检查，记录完整、空、失败和截断结果。未经来源确认的错误文字不作为结构化错误码依据。
4. 进入 Diagnosis 前检查问题清单和声明任务的查询覆盖。无法获取的证据保留原因；不强制遍历所有工具，也不将未知触发原因自动视为漏查。
5. Diagnosis 区分观测、机制、触发原因和竞争解释。只读建议须增加新覆盖，不能把已完成宽查询的子查询当作新取证。
6. Reviewer 独立核对支持、反证、替代解释及查询过滤假设，交接缺少的观测；Supervisor 规划具体补查。最多一轮补查。
7. 不能继续时带限制结束。来源观测、有效草稿、暂定假设和已分类待确认建议保留；未复核建议不能据此审批或执行。

## 本轮新增的程序约束

- Reviewer 将核心问题标为 not_required 或 blocking=false 时，REQUIRED_EVIDENCE_NEED 返回 N 编号、精确字段路径、错误状态、允许值及纠正说明。错误详情不复制模型的自由文本理由。
- 只读建议经过角色权限与范围校验后，依据同一运行查询台账检查新增覆盖。完整查询覆盖的窄查询以及同参数已尝试的检查返回 READ_ONLY_ACTION_ALREADY_COVERED。新类别、放宽未覆盖过滤等仍可作为建议；建议不自动执行。
- 业务错误耗尽原有一次纠正额度后，将错误码和字段位置写入报告信息缺口。有效草稿和已保留观测不会被这次拒绝覆盖。
- 不提升预算，不改为无限重试，不将程序覆盖判断当作因果正确性的证明。

## 验证与边界

新增本地控制验证：核心问题双条件定位、完整非空/空查询去重、受限空查询后的合法放宽、纠正反馈传递及耗尽后报告保留。

2026-10-11 验证结果：全套回归385项，378项通过、7项环境条件跳过；最后补充的重复建议纠正场景随本文件对应的7项专项检查全部通过。全套运行早于最后新增的该项测试；未为此重复整套回归。记录位于本地忽略目录 output/finite-convergence-regression.log。

本地脚本控制验证证明程序行为，不证明真实模型一定遵循调查策略。真实模型验证需独立的显式小预算执行；没有新增真实调用结果时，不宣称已改善模型准确率或多 Agent 优于单 Agent。

工作流能力：图编排与角色边界、共享证据状态、来源引用、权限范围、有限纠正和补查、失败可定位、人工审批执行。后续不以所有案例 completed 作为唯一目标。

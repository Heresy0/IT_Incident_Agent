# IT 故障 Agent 面试展示指南

新增[定向真实模型对照与回答依据](curated-live-guide.md)：两个展示案例加一次工单修订，共6次真实运行。真实复核片段与下述免费脚本控制演示分开报告；本轮观察到候选被独立复核保留为unresolved，没有完整诊断质量优势证明。

## 五分钟讲解

**第一分钟：问题与架构。** 项目把自然语言故障描述整理成有服务、环境、版本和时间范围的工单。五个角色在串行 LangGraph 中完成调度、当前取证、知识检索、诊断与独立节点复核。指标、日志、变更、负责人、手册和历史工单通过六个受限只读工具访问；建议与执行分离，修复必须经过后端权限校验和审批。

**第二分钟：历史经验核查。** 打开 history 场景。上一周扩容有效，本次却是400字段拒绝。指出 Knowledge 获取的历史适用前提、Investigation 的当前编码与负载证据，再看 Diagnosis 的H1以及被排除的H2。重点讲历史检索是线索，当前原因必须引用当前观测；角色拆分让知识适用性和来源责任可检查。

**第三分钟：冲突证据。** 打开 scope 场景。绿色 /health 和只读 metadata 探针不覆盖实际写入；403来自当前写身份，磁盘满来自已退役runner。查看来源引用与Reviewer逐项评估，说明“有错误日志”和“错误解释当前故障”需要分开判断。恢复建议必须用实际导出验证，不能只看探针绿色。

**第四分钟：质疑与补查。** 打开 rework，展开草稿与复核。初稿故意使用薄弱的历史DB CPU解释，第一轮复核拒绝该原因，并提出当前连接池指标与resource日志检查。实际工具台账记录一次补查；修订稿改为连接池耗尽候选，随后再次复核。说明返工最多一轮，具体只读参数仍受范围与预算校验，不会把“反思一下”当作已完成补查。

**第五分钟：Harness与取舍。** 介绍统一RunContext计数、收尾预留、结构校验、来源字段引用、查询去重、事件审计、工具角色权限与修复审批。调度者出错时可在剩余预算内做一次诊断收尾，关键证据不足仍返回partial。当前没有并行调度和checkpoint恢复；角色使用同一个基础模型，复核是程序固定的独立阶段，无法保证模型错误不相关。

## 如何复现

```powershell
cd D:\code\it_incident_agent
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe scripts/demo_interview.py
```

终端返回新的 `output/interview-demo/<批次>/`。直接打开 `index.html`，或仅把该批次目录作为静态站点提供：

```powershell
.\.venv\Scripts\python.exe -m http.server 8011 --bind 127.0.0.1 --directory "终端输出的批次绝对路径"
```

然后访问 `http://127.0.0.1:8011/`。停止静态服务器按 Ctrl+C；每次复现建立新目录，不覆盖历史批次。无需模型Key、数据库、Docker或其他项目。

## 高频追问

**为什么不用一个Agent？** 单Agent也能调用全部六个工具，项目保留了这条链路。多角色方案的价值是把中间职责、证据交接、独立复核和定向返工固化在程序中，使每个阶段的输入、输出、成本及拒绝原因可审查。是否值得额外成本取决于任务复杂度，当前真实对照没有证明总体质量领先。

**这是五个不同模型吗？** 真实路径使用同一个底层模型、五份角色提示和独立的局部消息历史，经过五个LangGraph节点。展示路径用脚本响应替换模型接口，控制流与工具执行器相同。不是五个独立训练的模型，也不是并行执行。

**Reviewer为什么能纠错？** 它取得原始观测和全部F/H/A目标，按相同完成规则逐项评估，可以拒绝薄弱原因，并提交具体工具、参数和预期区分价值。程序验证覆盖、引用、权限和预算，但不会自动证明语义正确；演示中的判断明确为预设控制响应。

**Harness在哪里？** `app/runtime/context.py`管理计数、预算及trace；`app/tools/executor.py`管理只读权限、范围、去重与工具结果；`app/evidence/`管理来源与引用；`app/workflow/`管理节点、任务检查、返工和收尾；`app/repairs/`实现审批后的受限操作与验证。模型负责提出决策，程序负责强制边界。

**做过真实接入吗？** 已有本地知识库系统的Prometheus/Loki登记和Worker停止、人工审批恢复、文档最终入库的开发闭环。可以展示对应保留材料。没有生产上线，不宣称高并发、企业规模或生产SLA。

**怎样评价效果？** 机械正确、业务语义、成本分别报告。既有真实对照保留全部partial与失败，脚本控制结果不计入准确率。离线演示证明机制可运行，不能据此声称实际模型一定能完成这些场景。

## 简历表述建议

基于LangGraph实现IT故障工单协作诊断系统，编排Supervisor、Investigation、Knowledge、Diagnosis和Reviewer五个角色；构建六类受权限与工单范围限制的只读工具，设计统一预算、结构与引用校验、查询去重和事件审计，并支持复核驱动的一轮定向补查及审批后的受限修复。通过本地知识库系统完成观测接入与Worker恢复开发验证，提供可复现的故障演示和单双Agent评测记录。

这段表述不添加未经验证的准确率、提升比例、线上规模或部署经历。

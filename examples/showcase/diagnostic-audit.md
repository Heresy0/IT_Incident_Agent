# 区分必要缺口、未完成调查与复核矛盾

后续曾针对本页剩余的无依据细节和过度阻塞问题实施[断言逐项复核与补查决策影响](claim-decision-review.md)，该实验现已撤回，应用恢复到本页的 v6 版本。本页的 14 份运行和后续实验报告保持原样，回退后的验证另见[版本回退记录](rollback-v6.md)。

这轮改动针对同一类 `partial` 混合多种原因的问题。报告分别记录机制是否获支持、下一步是否获支持、声明的查询是否执行完，以及流程停止原因；保持原有完成判定和人工审批边界。

## 实施方式

- 核心问题 N2 只评估近端机制，N3 评估会改变机制或下一步的替代机制。机制解释“当前如何失败”，触发解释“为何从这个时间开始失败”，后者未知不能直接代替前者未知，也不能挪入 N3 继续阻塞。触发信息确实影响操作条件时，须具体关联尚未获支持的行动。
- 真实多 Agent 的 Reviewer 若阻塞一个未知问题，需要给出 `ReviewBlocker`：因果层级、受影响目标、缺少的观测、不同结果如何改变判断、处理方式。已有明确关联问题的 `request_evidence` 保持兼容。
- 程序拒绝不存在的目标、机制问题混入触发问题、所有受影响目标已获支持却继续阻塞、缺少查询参数及越权查询。这些检查只发现契约和内部一致性问题，不证明因果成立；错误交回有界纠正，不自动提升结论。
- 有价值且尚未完成的合法检查交给 Supervisor 规划，继续遵守一次补查和原预算。Reviewer 的提示不直接执行，已查空的相同查询不重复补查。
- JSON 和 Markdown 报告新增 `diagnostic_audit`，保留每个声明查询的参数、目标、执行状态、证据与限制。

| 分类 | 可验证依据 | 解释边界 |
| --- | --- | --- |
| `investigation_incomplete` | 合法声明查询尚未执行 | 调查没有按声明完成 |
| `retrieval_failed` | 实际查询失败 | 不表示现实信息不存在 |
| `incomplete_sample` | 结果截断 | 不能按完整样本排除原因 |
| `selected_scope_insufficient` | 所选范围查空或没有所需样本 | 不能宣称整个渠道缺失 |
| `external_input_required` | Reviewer 声明需要范围外的信息 | 仍是模型判断，程序未证明其必要性 |
| `review_not_completed` | 没有有效 Reviewer 结果 | Supervisor 的支持不替代复核 |
| `unresolved_review` / `unexplained_blocker` | 复核状态及阻塞契约 | 留给语义审阅，不能自动消除 |
| `nonblocking_limitation` | 非阻塞问题 | 保留限制，不阻止已支持的诊断 |

`partial_origin` 独立记录预算/流程上限、协议/执行失败、未完成调查或复核/证据限制。因此一次运行可以同时有未执行检查和预算停止。`overblocking_suspected_need_ids` 仅提醒人工核对；各缺口明确记录 `semantic_necessity_verified_by_program=false`。

## 模型输出与验证

qwen3.7-plus 的真实调用曾返回 Markdown 围栏和说明文字，严格 JSON 契约因此失败。先启用原生 `response_format={"type":"json_object"}`，两次真实调用的工具→JSON 小测试通过，但后续完整案例仍在附带工具定义时出现解析失败。参数和真实响应追踪确认：小测试不能代表完整链路稳定。[阿里云结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

当前将读取和最终输出分开：模型仍自主选择登记工具；声明检查完成、最后一步或结构纠正时，使用没有工具定义的原模型返回 JSON。不额外增加调用、不接受围栏或从说明文字里截取 JSON；检查完成只触发解释阶段，不证明任务含义或机制已得到支持。若解释暴露已有覆盖缺口，原有有界检查反馈仍可要求新查询。SDK 边界回归验证了读取调用带工具、输出调用不带工具、严格拒绝围栏后的一次纠正及实际调用计数。

进一步在模型看到的 Schema 中限制机制/替代问题的阻塞层级，要求 Supervisor 显式写更新角色；提示及纠正反馈说明工具归属与工单时间边界。运行时权限校验继续独立执行。

完整运行记录见 [diagnostic-audit-runs.json](diagnostic-audit-runs.json)，保留每份原报告的 SHA256、源码指纹、失败原因、调用计数和审计状态。缺失的早期审计字段保持 null，不用最新解释重写历史结果。合成观测上的真实模型运行只能用于定位这些案例的行为，不能给出总体准确率。

## 实测过程与剩余问题（2026-10-11）

这轮所有完整运行都保留，包括初期配对单 Agent、多 Agent、追踪运行和账户欠费失败。欠费后的充值小调用通过，才恢复完整测试。工具→JSON 小测试、两次取证请求追踪和账户检查另记，不能叠加成更多质量案例。

| 阶段 | 多 Agent 实际结果 | 说明 |
| --- | --- | --- |
| 启用原生 JSON 前 | show_101 6 模型/2 工具；eval_002 13/4，均 MODEL_OUTPUT_INVALID | 取证围栏/说明文字、缺少 blocker 查询参数等 |
| 原生 JSON，仍绑定工具 | eval_002 15/4、126.500 秒；show_101 15/3、166.547 秒，均 partial | 分别仍有 5、4 次取证 JSON 失败，不能据小测试宣布修复 |
| 输出调用移除工具 | eval_002 13/4；show_101 7/2，均 partial/MODEL_OUTPUT_INVALID | 无取证 JSON 失败；剩余为复核层级矛盾及调度越界/错角色 |
| 增强 Schema 与反馈 | eval_002 8/2、73.766 秒，partial/REWORK_NOT_EXECUTED；show_101 6/2、57.359 秒，partial/TIMEOUT | 两者无协议校验失败；后者未完成有效复核，不能评价诊断质量 |
| 同源码、同预算重试超时案例 | show_101 14/4、143.860 秒，partial/REVIEW_INCOMPLETE | 无运行错误、无协议失败；支持机制和下一步，N4 的变更查询尚未执行 |

最新认证案例将配置/依赖拒绝机制与发布触发问题分开，N2 获支持，N3 不再以纯触发未知阻塞；人工核实预期配置的建议获支持。Reviewer 仍请求发布审批/基线资料，Supervisor 判断无法在登记渠道取得，保留 partial。这只能证明系统保留并解释请求，不能证明该请求对当前下一步必不可少。

辅助语义审阅还发现该案例 H1 中“客户端仍使用 portal-stage 令牌”没有所选来源支持，Reviewer 未拦截；早期 JSON 模式认证案例的“签名校验被拒”也与已取得的签名校验成功记录不一致。因此这轮改善的是结构输出、阻塞契约及可审计的降级，不能宣称因果判断或复核质量已经稳定。系统仍可能过度请求触发信息，独立 `request_evidence` 的语义必要性也需要人工核对。

推送复测支持 encoder v2 与接收端 v1/UNKNOWN_FIELD 的兼容性机制，建议合法的新变更核查；该检查尚未执行，报告明确归为 `investigation_incomplete`，而非渠道不存在。同时 N4 以“意外变更需回滚、计划部署需协调升级”说明阻塞的行动影响，仍需人工评估这个二分是否有充分依据。N3 将低 CPU 样本写成“排除资源瓶颈”也偏强；这属于语义复核风险，不算结构协议失败。最新两个有效案例均无结构纠正，仍为 partial，不能把局部改善表述成完成率提升。

共保留 14 份完整报告（包括两份单 Agent 初期对照、追踪和欠费失败），后续阶段没有再配对单 Agent，也没有正式人工评分，不能声称多 Agent 胜出。

最终应用指纹 `6e92f8fc6db68a0b`；全量回归 426 项，419 通过、7 项数据库集成按条件跳过，65.451 秒。测试命令：`PYTHONPATH=app python -m unittest discover -s tests -t .`。数据库跳过与真实模型结果不计作通过的质量案例。

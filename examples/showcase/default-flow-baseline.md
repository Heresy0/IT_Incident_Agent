# 当前默认流程冻结基线

2026-10-13 按用户要求冻结当前默认流程。Git 标签为 `codex/default-flow-2026-10-13`，对应提交保存本次会话的现有实现、测试、示例和资料清理结果。冻结只建立可追溯基线，不改变运行行为、不扩大预算、不新增模型验证。机器可读设置和验证摘要见 [default-flow-baseline.json](default-flow-baseline.json)。

## 固定的源码默认行为

| 项目 | 基线行为 |
| --- | --- |
| 默认真实诊断 | Supervisor 结构化规划 → 程序执行 Investigation / Knowledge → Diagnosis → Reviewer → 报告 |
| Knowledge 查询 | 执行 Supervisor 的 checks；默认不调用独立知识规划模型 |
| 并行取证 | 两类任务独立且原门禁允许时并行，其他情况顺序执行 |
| 正式复核 | 直接核验原始证据、问题台账和诊断草稿；默认不增加观测盲审 |
| 协议纠正 | 默认程序取证模式下，Supervisor、Diagnosis、Reviewer 全运行各最多纠正一次，计入原总预算 |
| 反证保护 | 默认 bounded_refutation_v1；弱化解释、缺少支持、缺少分类或当前范围依据不足时保留为不确定 |
| 诊断包 | 仍需显式传入 Python 参数，普通 API 和 CLI 不自动加载 |
| 轻量 RAG | 由已有服务的 observations.runbook_rag 开启；本地 JSON 向量索引、余弦相似度和原文引用 |
| RAG 默认参数 | 每片 500 字、重叠 50 字；最多 200 片；Top-K 为 3，最多 4；相似度门槛 0.35 |
| 常规调度限制 | 最多 4 次调度、6 个任务、1 轮补查 |
| 额外补查 | 原有区分价值、新查询、收尾预算等门禁全部通过时，至多追加一轮；不自动扩大总预算 |
| 修复 | 独立人工提案与审批、精确登记执行器、有界恢复验证；不因复核通过自动执行 |

普通 Python 协作入口的默认额度为 16 次模型、24 次工具、180 秒，输入上限 28000 字符，预留 3 次模型及 20 秒收尾。普通 API 未提供预算时使用相同模型／工具默认数；显式请求预算、显式 Python limits 和独立评测入口仍按各自原规则工作。

真实模型通过原兼容接口调用，单次超时 30 秒，SDK 自动重试为零。脚本演示 API 保留原 Agent 执行模式，只用于控制验证，不能把其行为或成绩当作默认真实诊断结果。

代码默认模型与嵌入参数随标签保存；实际模型名称、地址、凭据、服务登记和部署环境仍可通过现有配置指定。本基线不保存真实 .env、令牌、services.local.json、本地手册索引或数据库内容。因此复现实验还需记录当次模型、预算和数据版本。

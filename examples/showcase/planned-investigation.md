# 默认计划取证与直接复核

实施前的现有改动已保存为 Git 提交 `ae6b964`。本轮保留 Investigation 的取证职责，将默认执行方式从独立模型选择工具改为程序执行 Supervisor 的已校验计划。

## 默认流程

Supervisor 规划具体 checks → Investigation 程序执行 → Diagnosis 解释原始证据 → Reviewer 直接复核 → 有价值的新补查或明确的信息交接 → 人工确认。

- 默认 `investigation_mode='programmatic'`，取证阶段没有模型调用，不自行添加查询、不生成事实摘要或因果假设。
- Supervisor 的 Investigation 任务必须有明确的登记工具和参数；缺失计划进入有界纠正，程序不能仅凭自然语言目标猜工具。
- 原身份、角色、服务、环境、时间、参数与预算门禁继续适用。空查询、失败、截断分别保存在实际查询台账中。
- 已尝试或已覆盖查询复用台账，失败不自动重试。补查计划混有重复检查时只保留新检查；全部没有新覆盖时保留缺口并交接，不把它当成诊断通过。
- Knowledge 仍为可选检索角色，历史资料不证明当前故障。Diagnosis 与 Reviewer 读取原始证据和实际查询状态，不将查询完成等同于机制证实。
- 默认关闭观测盲审。直接 Reviewer 仍有全部引用、目标覆盖、操作条件和阻塞审计校验；真实模型的阻塞未知仍须解释受影响目标、缺失观测及判断变化。
- 症状、机制问题的阻塞属性由程序固定。Reviewer 对核心问题省略 blocking；若返回该字段，程序记录并忽略它，既不关闭阻塞，也不提升证据结论。无效引用、核心 not_required、矛盾的缺口仍拒绝。
- 保留原 `agent` 和显式 `blind_review=True` 对照路径。免费脚本演示明确使用旧 Agent 模式，避免将预设模型响应包装成新流程的质量证据。
- 保留原整体预算、有限补查轮次和纠正次数，未增加重试层。阶段预算估算仍保守预留旧取证解释的调用余量，暂不继续调整预算计算。

## 验证方法

新增默认流程、API 入口、真实执行器和复用/失败边界测试；历史 Agent 回归明确指定 `investigation_mode='agent'`。验证不只检查计数：默认取证模型被设置为一旦调用即失败，仍须执行有效查询、产出可审阅草稿并完成直接复核。混合重复与新检查必须保留新检查；越界查询不能被复用逻辑掩盖。

真实验证使用当前配置的 `qwen3.7-flash`，只读取冻结合成场景。每个源码版本、场景固定一次，不隐藏失败，不用参考答案引导模型。额度为每次 32 模型 / 48 工具 / 300 秒，预留 2 模型 / 15 秒；费用未知。

| fresh_002 | 5 / 3 | 45.328 秒 | partial；Diagnosis 得到证书过期观测，Reviewer 连续两次 N3 阻塞范围不合法，未完成复核，建议保留为待审。 |

最终源码 `397dab6948cc1ba4` 的 fresh_001：7 模型 / 5 工具，64.516 秒，Investigation 模型为零，无执行错误；Supervisor 首次参数不合法，使用原纠正额度后恢复。实际查询已取得 resource 日志的 ENOSPC 与可用字节为零，Reviewer 支持“归档卷容量耗尽导致写入失败”和需人工批准的有条件清理/扩容建议。触发未知仍被追问，Supervisor 未安排新查询，保守结束为 partial / REWORK_NOT_EXECUTED，未宣称完成或解决。

## 结果解释与限制

取证阶段的保留有必要：它承接受限工具执行、台账、失败和证据交接。默认流程不再需要一个独立取证模型重复解释 Supervisor 的计划。

取证程序只保证合法计划按预算执行，不能保证 Supervisor 选择了所有必要证据，也不能保证 Diagnosis/Reviewer 的语义判断正确。本轮真实验证仍发现漏查资源、缺口归属不合法和偏向外部原因的建议；这些按质量问题记录，不通过放宽校验或反复运行挑选成功来消除。

最终报告仍有语义局限：Reviewer 把一次远端探测成功用于反驳远端写入策略/配额问题，反证强度偏高；探测成功通常不能排除写入专属约束。同时，非关键触发未知仍可能阻碍流程收尾。本轮没有为通过案例自动更改这些结论。

直接审阅可能更受诊断草稿影响，保留盲审便于后续对照；当前小样本、同模型和作者审阅无法验证该风险的实际幅度。所有建议仍进入人工确认，未经完整复核的建议不得当成已批准修复。
